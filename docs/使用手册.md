# Paper Atlas 使用手册

## 你只需要做什么

在 Codex 里打开本仓库作为项目。上传 PDF，或提供论文链接，说：

> 阅读这篇论文，按仓库规范收录并同步到 GitHub。

不必先写阅读笔记。不需要启动网页后台、填写摘要、单独购买 API。这个版本由 Codex 当前会话执行总结；仓库中的 AGENTS.md 和 ingest-paper 技能使步骤可以复用。网页只是阅读界面，不执行 AI 收录。

如果在另一个项目里读论文，需要明确告诉 Codex 本仓库地址或本地路径，并让它读取仓库 AGENTS.md。它不能知道其他聊天里读过哪些论文，也不会后台监听所有聊天。用户上传并要求阅读整理时收录，用户仅提及论文或只问局部问题时不自动标记已读。

常见说法：

- “阅读并收录这个 PDF，完成后同步网页。”
- “把这三篇论文逐篇阅读全文并收录；有失败的列出来。”
- “更新这篇 benchmark 的总结，核对它的任务规模与评分设置。”
- “只讨论这篇论文，暂时不保存。”
- “找出库里的工具调用 benchmark，对比任务规模、评分方式和运行成本。”

## 一篇论文会经过什么

1. 登记论文来源、稳定 id 和本次文件哈希；检查是否重复收录。
2. PDF 提取文字并标记物理页号，或读取全文网页。阅读方法、实验和限制；重要图表需查看原页。
3. 按 prompts/summarize.md 和固定章节生成中文卡片。研究主题和受控标签来自 config.json。
4. 保存可追溯的短摘录、章节及页码，并将结论与证据关联。
5. 按 prompts/review.md 检查机制、评测设置、贡献边界与压缩损失，并确认公开内容仅来自论文与官方来源。
6. 程序逐页匹配摘录、检查分类和关联，再生成 Markdown 和网页数据。
7. 获得同步授权后提交本次文件并推送。GitHub Actions 校验通过后部署网页。

处理失败会保留在 inbox，查看命令：`python scripts/kb.py queue`。扫描件、付费墙和缺页不应变成编造全文的理由。扫描件需要先 OCR；目前没有内置 OCR。链接只返回摘要或登录页时应换成可读 PDF。HTML 的证据用章节定位，page=1 不是论文的物理第一页。

## 改研究主题或压缩方式

- **主题边界和分类**：修改 config.json 的 research_topic、scope、research_questions 和 topics。
- **每篇如何解释**：修改 prompts/summarize.md，先改问题视角和保留信息，不随意增加重复字段。
- **检查哪些失真**：修改 prompts/review.md。
- **固定章节**：改 scripts/kb.py 的 SECTIONS，并同步 templates/paper.md、docs/schema.md 和测试。旧卡片也要迁移到新结构。
- **网页样式**：web/style.css；网页行为：web/app.js。无需打包器。

建议以后新论文继续使用相同骨架，将主题特有维度放进方法、实验、局限和研究关联中。标签用于检索，不能代替解释。新增标签不自动修改旧卡片；让 Codex根据已有正文检查是否需要重分类。

公开内容仅整理论文和官方资料。聊天中的私人研究计划和未发表观点不应写入公开仓库；“与研究主题的关系”只描述与配置中公开主题的关系。

## 第一次在本机安装

```bash
git clone https://github.com/w1ndz321/paper-atlas.git
cd paper-atlas
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

在 Codex 中选择这个文件夹作为项目。正常情况下它会发现仓库技能；也可以直接说“读取 .agents/skills/ingest-paper/SKILL.md，按其收录这篇论文”。无需安装全局技能。

## 给 Codex 的命令参考

```bash
# 论文链接；arXiv abs 自动取 PDF
python scripts/kb.py prepare --id my-paper --url https://arxiv.org/abs/2406.12045v1

# 本地 PDF，也可同时指定官方来源链接
python scripts/kb.py prepare --id my-paper --pdf /path/to/paper.pdf

# Codex 读 .local/my-paper/fulltext.txt 并填写 draft.json、复核后
python scripts/kb.py finalize --draft .local/my-paper/draft.json

# 修订已有论文：上述 prepare 与 finalize 均加 --update
# 查询和构建
python scripts/kb.py search "最终状态"
python scripts/kb.py validate
python scripts/kb.py render --check
python scripts/kb.py build
python -m http.server 8000 --directory dist
```

首次 prepare 会生成完整空草稿。它不是已收录卡片，不能直接发布。finalize 要求全文阅读、证据和压缩复核完成；没有单独要求用户审批，因为用户已要求 Codex 完成收录。

重读修订保留同一 id 和 added_at。不同版本通过官方版本链接、sha256 和 Git 历史追溯。旧数据不会静默覆盖：更新必须显式使用 --update。批量处理结束检查队列，确保每篇都是已完成或有明确原因的待处理。

本地 PDF 会复制到 attachments 并随提交保存，网页的原文入口优先指向官方链接，没有链接时指向仓库 PDF。网上已有原文的论文默认保存来源链接及卡片，不额外把完整 PDF 缓存提交。提取全文和草稿只在 .local，不进入网站。

## GitHub 与网页

本仓库的正式地址和网页入口见 README。首次启用时，在仓库 Settings → Pages → Build and deployment 选择 **GitHub Actions**。工作流为 .github/workflows/pages.yml；推送 main 后会依次验证、构建、部署。失败时网站保留上次成功版本，查看 Actions 的失败步骤。

通常使用：在 Codex 明确说“收录并同步到 GitHub”。Codex 应查看 git diff，只提交本次卡片、生成 Markdown、必要附件及队列变化。不要把 .local、凭据和无关本地文件提交。没有同步授权时只本地保存并说明状态。

网站支持标题/作者/正文/关键词搜索，受控主题与类型筛选，最近收录/年份排序，论文详情、证据跳转、相关论文和原文链接。搜索过滤状态与单篇链接可直接收藏或分享。手机和桌面均可阅读。

## 这个版本的边界

它让 Codex 执行重复的读文收录流程，并在推送后自动发布；不会在 Codex 关闭时自行替你读新论文，不跨聊天监控阅读行为。没有额外模型 API 调用、云数据库或定时抓取任务。

自动校验保证结构和引用一致，不证明论文结论正确，也不代替独立复现实验。卡片的 reviewed_by=Codex 表示本轮来源与压缩复核，不表示人工专家审稿。关键研究决策仍可沿证据回到原文。
