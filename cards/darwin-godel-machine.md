# Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents

用冻结底座的编码 Agent 改写自身工具与工作流，并保存多条演化分支作为后续改进的踏脚石。

- 作者：Jenny Zhang, Shengran Hu, Cong Lu, Robert Lange, Jeff Clune
- 年份：2025 · 类型：framework
- 主题：RSI · 递归自我改进
- [原文](https://arxiv.org/abs/2505.22954v3) · 收录：2026-11-10 · 更新：2026-11-11

- 子类：Agent 与代码自改

归类依据（知识库分析）：演化后的编码 Agent 实际参与后续自身代码修改，形成结构回流；任务成绩与后续改进能力仍须分开评价，固定指令生成与档案选择不被隐去。

## 递归闭环与证据边界（知识库分析）

- 证据状态：结构闭环 · 改进增益未定

- 下一轮职责：演化后的父 Agent 在后续迭代修改自身程序。

- 固定组件：底座模型、指令生成部分、档案维护和父代采样固定。

- 改进能力证据：编码任务分数是任务能力证据；不能直接等同于固定预算下改进效率独立增强。

## 研究问题

能否让编码 Agent 改写自身实现，并积累可供未来改进使用的历史版本？DGM 将“修改自己的仓库”视为编码任务，以编码 benchmark 作为能力代理。本文核对版本为 arXiv v3、ICLR 2026，首次公开年份为 2025。

证据：e1, e2

## 原有做法与缺口

理论 Gödel Machine 要求先证明修改有益，实际复杂系统中很难做到。只保留最新或最高分版本又可能丢掉暂时退步却有潜力的分支。DGM 用经验评测替代证明，并以版本档案维持多样化搜索；这不等于获得理论最优或无限进步保证。

证据：e1

## 核心方法

从档案中按表现与已生成后代数采样父 Agent。父 Agent 分析日志、提出功能改进并改写自己的代码；子代通过编译和基本代码编辑检查后进入档案，再以编码任务分数参与后续选择。底座冻结，档案维护及父代采样程序固定、不能自修改。

证据：e1, e2

## 一个具体例子

初始编辑工具一次查看或替换整个文件。演化出的版本增加按行查看、字符串精确替换、上下文总结以及多候选补丁排序。图 3 的最终谱系还经过两次分数下降：这些中间版本没有被丢弃，后续分支在其基础上得到更好 Agent。

证据：e4

## 输入与产出

输入为初始 Python Agent、冻结 FM、编码任务、评测器及搜索设置；输出为 Agent 版本档案、源码差异、谱系与分数。SWE-bench 使用 Verified 子集；Polyglot 报 pass@1，不让任务执行 Agent看到真实测试反馈，不能直接等同排行榜的 pass@2。

证据：e1, e3

## 关键结果与实验条件

每个主搜索运行 80 轮；自修改用 Claude 3.5 Sonnet (New)，SWE 评估也用该模型，Polyglot 评估用 o3-mini。SWE 的 200 题评估由 20.0% 到 50.0%；Polyglot 搜索的 50 题子集由 14.0% 到 38.0%，全 225 题复评则由 14.2% 到 30.7%。去掉自修改或开放档案的消融较弱，并报告跨模型、跨 benchmark 迁移。

证据：e2, e3

## 主要贡献

将源码自修改、编码能力评估与开放式版本档案结合，展示工具和工作流可自动演化。分支谱系使较差中间解也能为后续发现提供组件，而不是只按眼前最佳分数爬山。贡献在经验系统设计，不是完成原始 Gödel Machine 的证明义务。

证据：e1, e4

## 局限与适用边界

“编码成绩反映自我改进能力”是重要假设。任务与评估仍由人定义，底座与开放式搜索过程固定；没有重训基础模型，也未证明长期自我加速。搜索中使用 benchmark 子集做选择，需将其与跨 benchmark 留出测试分开理解。

证据：e2, e5

## 成本与复现条件

SWE 主运行约两周，并有显著 API 开销。复现要匹配论文 v3 的模型版本、80 轮设置、分阶段题集、并行度、工具和隔离执行环境；公开实现与谱系便于追踪，但本库未独立重跑。

证据：e5

## 与研究主题的关系

知识库分析：RSI 的 Agent 源码演化代表作。适合与 STOP 比较单一优化器和多分支档案，与 AIDE²比较编码代理目标和直接研究效率目标。论文讨论可解释性风险，但并未验证机制解释驱动的 RSI。

研究关联分析；未作为论文结论。
