# DSGym: A Holistic Framework for Evaluating and Training Data Science Agents

DSGym 用统一的容器执行环境评测数据科学 Agent，过滤不读数据也能答对的任务，并用经执行与审核的分析轨迹微调小模型。

- 作者：Fan Nie, Junlin Wang, Harper Hua, Federico Bianchi, Yongchan Kwon, Zhenting Qi, Owen Queen, Shang Zhu, James Zou
- 年份：2026 · 类型：framework
- 主题：AI4S Agent 评测
- [原文](https://arxiv.org/abs/2601.16344v1) · 收录：2026-11-25 · 更新：2026-11-25

- 子类：科学领域基准 / 过程评价与失败诊断 / 评测方法与有效性

归类依据（知识库分析）：DSBio 提供生物信息学科学任务，执行轨迹用于失败诊断，去数据对照和捷径过滤用于检查评测有效性，分别对应三个既有子类。训练示例为监督微调，不构成递归自我改进。

## 研究问题

数据科学 Agent 答对一道题，是否真的读懂并分析了数据？作者发现，部分带数据文件的基准在撤走文件后仍能被解答；模型可能靠常识、题目线索或记忆得到答案。DSGym 要解决的核心问题，是在可复现的环境中衡量真实数据分析能力，并检查通用分析成绩能否延伸到科学工作流和完整预测建模。

证据：e1, e2

## 原有做法与缺口

既有基准的输入格式、评分规则和执行环境不同，难以直接比较；有些题目还存在答案缺失、选项重复或格式要求不一致。任务覆盖又偏向常规统计与表格处理，较少涉及单细胞数据、专业软件和领域概念。因此，统一 API 之外，还需要审核题目质量、验证数据依赖，并补上专业任务。

证据：e2, e3

## 核心方法

DSGym 将任务统一表示为数据文件、问题、评价指标与元数据。管理容器为每条 Agent 轨迹分配独立工作容器：数据只读挂载，工作区可写，Jupyter 内核保留变量和中间结果。默认 Agent 逐步规划、执行 Python、读取反馈，再提交答案或预测文件；评分在独立进程进行。

任务筛选分两步：先人工清理无效题和答案格式，再让 5 个前沿模型在看不到数据时答题；若至少 3 个模型答对，就剔除该题。新增 DSBio 则由专家从论文发现或后续分析构造问题、提供标准 Notebook，再由另一位专家独立解答复核。

训练示例采用“先探索再验证”：Agent 自己读数据出题并计算参考答案，随后在新环境以温度 0.8 采样候选轨迹；LLM 审核问题可解性、执行正确性和答案依据，再去除语义重复。3,700 个候选最终留下 2,000 对，用于 Qwen3-4B 的监督微调。

证据：e4, e3, e5, e6

## 一个具体例子

附录 B.1 展示了一个领域理解失败：题目要求比较 LHS 与 LASP 细胞中 ESR1、FOXA1、GATA3 的平均 RNA 表达。GPT‑5.1 载入 .h5ad 后，把 LHS_sub 和 LASP_sub 两个亚型字段误当成主要细胞类型标签，按错误分组计算，答成 GATA3；标准答案为 ESR1。正确分组应使用 author_cell_type。这说明代码能够运行、均值也算出来，仍可能因为元数据的生物学含义读错而分析失败；DSGym 的轨迹记录让这种错误可追查。

证据：e7

## 输入与产出

框架接收数据、问题、期望答案格式、指标、模型和环境配置，输出执行轨迹、最终答案或 submission.csv，以及评分。表 1 汇总任务生态为 972 道分析题和 114 个预测任务，其中包含新建的 90 道 DSBio，以及 DSPredict 的 38 个容易竞赛和 54 个困难竞赛，也集成 MLEBench-Lite。分析题以允许轻微数值误差的精确匹配计分；预测题使用竞赛原定指标与排行榜。这里评价的是给定问题后的数据驱动研究环节，不覆盖从零提出科学假设的全部发现过程。

证据：e8, e9, e4

## 关键结果与实验条件

主评测使用默认 CodeAct 风格 Agent、温度 0，并关闭包括搜索在内的附加工具；GPT‑5.1 等模型另比较推理强度。DSBio 总准确率最高为 Kimi K2 的 43.33%，Sonnet 4.5 为 42.22%。作者对 4 个模型、每类任务各抽取 50 条失败轨迹，人工标注主要错误；DSBio 的领域理解错误占这些抽样失败的 85%–96%，不能读成全部题目的错误率。

表 5 展示了 2,000 对执行验证数据的微调效果。下列数值均为任务答案准确率（%，越高越好），不是相对提升；不同列的题目不同，不宜横向比较难度。

| 任务 | Qwen3-4B 原模型 | DSGym-SFT | GPT‑4o |
| --- | --- | --- | --- |
| QRData-Verified | 45.27 | 59.36 | 60.24 |
| DABStep-easy | 58.33 | 77.78 | 73.61 |
| DABStep-hard | 2.90 | 33.07 | 7.41 |
| DAEval-Verified | 64.47 | 86.19 | 92.26 |
| DSBio | 6.67 | 21.11 | 33.33 |

微调模型在两列 DABStep 超过 GPT‑4o，未在所有任务上超过它。表 4 的 DSPredict-Hard 私有测试中，GPT‑5.1 高推理配置的有效提交率为 85.7%，超过排行榜中位数的比例仅 14.3%，获任意奖牌比例为 4.8%。三个比例都越高越好，但分别衡量文件合规、成绩超过中位和达到奖牌门槛；有效提交只检查文件、行数与列名，不能证明模型有竞争力。

证据：e9, e10, e11, e12, e13

## 主要贡献

这项工作把统一任务格式、隔离执行、独立评分、基准审计与轨迹训练放进同一套基础设施。DSBio 增加专业科学分析，DSPredict 增加端到端预测建模；两者共同暴露了“会写代码”与“正确理解科学问题、持续优化模型”之间的差距。训练实验还说明，执行验证轨迹能帮助小模型改善复杂分析表现，但并未实现强化学习训练或自动改进器的递归升级。

证据：e1, e6, e14

## 局限与适用边界

当前任务强调确定答案，不覆盖以可视化为主的任务和多种解释都可能合理的开放探索。科学分析主要用生物信息学作为试点，不能代表全部科学领域。知识库分析：5 模型多数票筛出的只是该组模型能无数据解答的任务，不能保证剩余任务不存在其他捷径；领域错误标签也来自有限抽样。

v1 的规模与划分报告有些细节需复现时核对：DSBio 附录表 S1 的单细胞/空间题数为 56/13，而表 3 的分项百分比并不完全对应这组分母；预测表也未明确每列实际参评的完整任务清单。训练部分未充分交代种子题、合成题与评测题的隔离细节，也未提供充分的重复运行方差或置信区间，不宜把单表差值当成精确泛化保证。

证据：e14, e15, e12

## 成本与复现条件

复现需要 Docker、Jupyter、数据和领域依赖；容器可配置 CPU、内存与时间限制。DSPredict 的筛选规则要求数据规模小于 15 GB，但这不适用于所有集成基准。微调使用 LlamaFactory，学习率 2×10⁻⁵、6 个 epoch、batch size 8、梯度累积 16、warmup 比例 0.1。论文未清楚报告统一逐题步数/时限、GPU 总时长、训练总费用或合成与审核 token 成本，因此无法据此估计完整复现预算。

证据：e4, e13

## 与研究主题的关系

知识库分析：DSGym 同时关联科学领域基准、过程评价与失败诊断、评测方法与有效性。去数据对照检查“答对是否需要数据”，领域任务检查“通用分析能力是否迁移”，轨迹案例检查“错误发生在哪一步”。它与 Many AI Analysts 互补：DSGym 强调确定性任务的评分与数据依赖，后者提醒同一数据上合理分析也可能产生不同结论，不能把二者的正确性标准直接混用。

研究关联分析；未作为论文结论。
