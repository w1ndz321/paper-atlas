# NatureBench: Can Coding Agents Match the Published SOTA of Nature-Family Papers?

将 Nature 系列论文转为 90 个容器化科研任务，隐藏源方法，让编码 Agent 独立求解，并以相对已发表 SOTA 的差距评分。

- 作者：Yuru Wang, Lejun Cheng, Yuxin Zuo, Sihang Zeng, Bingxiang He, Che Jiang, Junlin Yang, Yuchong Wang, Kaikai Zhao, Weifeng Huang, Kai Tian, Zhenzhao Yuan, Jincheng Zhong, Weizhi Wang, Ning Ding, Bowen Zhou, Kaiyan Zhang
- 年份：2026 · 类型：benchmark
- 主题：AI4S Agent 评测
- [原文](https://arxiv.org/abs/2606.24530v1) · 收录：2026-11-10 · 更新：2026-11-12

- 子类：科学领域基准 / 评测方法与有效性

归类依据（知识库分析）：以生物、分子及物理建模任务测科研编码与已发表结果对标；参考方法隐藏，任务是独立求解，不统一归为照论文复现。

## 研究问题

编码 Agent 在只获得科学问题、数据和交付要求时，能否达到或超过已发表论文的结果？NatureBench 将评测目标放在独立求解科学任务，而不仅是照着论文复写方法。v1 共 90 个任务，涵盖细胞组学、蛋白质、生物医学建模、物理建模、分子设计和关系推理。

证据：e1

## 原有做法与缺口

现有论文复现任务主要测实现已知方法，部分工程基准又缺少自然科学场景与稳定可重跑环境。作者通过统一任务包与隐藏源方法，尝试把科研问题、运行环境、评分器和已发表结果锚点放进同一协议。

证据：e1, e2

## 核心方法

**NatureGym 流水线**按三个阶段构建任务，每个阶段均配备审查与修复：
1. **论文筛选**：挑选具备清晰数据与可评测科学目标的 Nature 系列论文。
2. **数据获取验证**：检查数据可访问性与运行依赖。
3. **任务包构建**：封装隔离容器；Agent 只看到任务说明与输入数据，参考答案与评测器保留在宿主服务中，提交后返回评分反馈。

每个测试实例先计算相对于已发表 SOTA 的差距，再在任务内汇总：
$$g = \mathrm{dir} \times \frac{m - m_{\mathrm{sota}}}{|m_{\mathrm{sota}}|}$$
- $g \ge 0$ 记作 `Match-SOTA`。
- $g > 0.1$ 记作 `Surpass-SOTA`。

证据：e2, e3

## 一个具体例子

图 5 与附录 C 的**癌基因识别**案例展示了任务从输入走到对标得分的完整链路：
- **输入**：生物网络邻接矩阵、64 维多组学特征、训练/验证标签以及测试掩码。
- **交付与评分**：Agent 需输出测试节点的 `predictions.npy`，宿主隐藏评测器计算 AUPRC 并与源论文对比。
- **结果与边界**：Claude Opus 4.7 经图模型、集成与训练优化后，该案例最佳聚合差距为 $g = 0.17666$；这只说明单个任务切片达标，不代表整篇源论文都已被复现。

证据：e5, e8

## 输入与产出

输入是隔离环境里的问题说明、数据描述和数据文件；产出是可执行方案、预测或其他约定提交文件。评测服务保存隐藏参考答案、指标和 SOTA 锚点；运行后还用模型评审检查伪造输出或利用反馈等捷径。任务包、环境流水线与公开榜单共同构成项目交付物。

证据：e2, e3, e5

## 关键结果与实验条件

固定引用 **arXiv v1** 报告，不与持续更新的在线榜单混用。10 个模型配置分别通过 Claude Code、Codex CLI 或 Gemini CLI 运行（禁用网页搜索，每任务限时 4 小时并按需分配 GPU）。最强配置 **Claude Opus 4.7** 支撑“Agent 能在近半任务匹配论文结果、但显著超越仍少数”的核心结论：

| 指标与判定口径 | 实测结果（Claude Opus 4.7） | 数值含义与判读边界 |
| --- | --- | --- |
| `Match-SOTA`（$g \ge 0$ 任务占比 ↑） | **47.8%**（90 题，表 4） | 表示接近半数任务切片达到或超过了源论文已发表 SOTA，**但达标不等于提出新科学方法** |
| `Surpass-SOTA`（$g > 0.1$ 任务占比 ↑） | **17.8%**（90 题，表 4） | 表示相对源论文 SOTA 净提升超过 **10%** 的任务比例，门槛更严格、占比明显更低 |
| 癌基因识别案例差距 $g$（↑） | **0.17666**（附录 C，图 5/表 8） | 测试集 AUPRC 相对源方法提升约 **17.67%**，仅反映单任务切片而非整篇论文完全复现 |

证据：e3, e4, e5, e8

## 主要贡献

提供从论文到可重跑科研任务包的 NatureGym，以及以论文报告结果为锚点的跨学科 benchmark。评测将有效提交、指标达标和运行后的捷径审查组合起来，既报告得分，也分析方法选择和执行资源方面的失败。

证据：e1, e2, e3

## 局限与适用边界

- **覆盖范围有限**：任务只覆盖可自动评分、数据可获得且能被环境封装的研究切片，论文明确提醒分数不代表整篇源论文。
- **泄漏与投机风险**：公开数据和迭代评分反馈仍有泄题或投机可能，协议通过禁用搜索与事后模型检查加以约束。
- **指标分布偏斜**：当 $m_{\mathrm{sota}}$ 分母很小时相对差距会被放大，均值容易出现重尾，因此必须结合阈值成功率和中位数一起看。

证据：e3, e6

## 成本与复现条件

统一时间预算为每任务 4 小时（评分期间暂停计时），90 个任务的硬件分配如下：
| 硬件配置 | 任务数 |
| --- | --- |
| 仅 CPU | 3 |
| 单张 RTX 3090 / 4090 | 70 |
| 单张 A800 | 17 |

附录 D 报告有效且有使用记录的运行成本，例如 **Claude Opus 4.7** 平均 API 成本为 $21.65；该数字不包含全部机器费用，也不是当前实时报价。

证据：e3, e7, e9

## 与研究主题的关系

知识库分析：这是科研编码 Agent benchmark 的实例，适合查看任务构建、可重跑环境、隐藏评分与论文结果对标的完整链条。与 ScienceAgentBench 对照时应保留两者目标不同：满足任务专用标准，与达到源论文 SOTA，不能直接视为同一难度或同一指标。

证据：e1, e3
